当客户联系其银行或发卡机构要求撤销一笔已完成的付款时，就会发生争议（也称为拒付）。OwnPay 会跟踪每个争议的完整生命周期，并在您的账本中记录其财务影响。

## 查看争议 {#viewing-disputes}

前往 **Reports \> Disputes**。表格列出所有争议，包含以下列：

| 列 | 描述 |
| --- | --- |
| **Transaction ID** | 被争议的原始付款 |
| **Amount** | 争议金额 |
| **Status** | Open、Under Review、Won、Lost 或 Closed |
| **Deadline** | 您必须提交证据的截止日期 |
| **Reason** | 客户陈述的争议原因 |
| **Gateway** | 处理该争议的支付网关 |

## 回应争议 {#responding-to-a-dispute}

<Steps>
  <Step>
    点击争议行打开其详情视图。
  </Step>
  <Step>
    查看客户的争议原因和原始交易详情。
  </Step>
  <Step>
    在 **Evidence** 部分下，上传支持性文件，例如送货回执、服务日志、沟通记录或任何履约证明。
  </Step>
  <Step>
    为您的团队添加内部**备注**。这些备注是私密的，不会发送给银行。
  </Step>
  <Step>
    在截止日期前点击 **Submit Response**。
  </Step>
</Steps>

<Warning>
  错过争议截止日期几乎总会导致自动败诉。请为 `dispute.opened` 事件设置 [webhook 通知](/zh/notifications/webhooks)，以便您的团队立即收到提醒。
</Warning>

## 争议结果 {#dispute-outcomes}

<Columns>
  <Column>
### 胜诉 {#won}

    - 争议金额会退回到您的账本余额
    - 网关不收取额外费用（因服务商而异）
    - 交易状态恢复为已完成
  </Column>
  <Column>
### 败诉 {#lost}

    - 争议金额会从您的账本中扣除
    - 同时还会扣除一笔**争议费**（由卡组织收取）
    - 该交易会被永久标记为已争议
  </Column>
</Columns>

## 预防最佳实践 {#prevention-best-practices}

- 使用清晰的付款描述，以便客户在对账单上识别扣款
- 主动提供订单确认和送货回执
- 在客户咨询升级为拒付之前及时回应
- 为每笔交易保留详细且易于获取的记录，以便提交证据
