## 🏆 旗舰特性 - 自主白标架构 {#🏆-flagship-sovereign-white-label-architecture}

> **OwnPay 是首个在单次安装中实现完整白标、多品牌、自定义域名结账架构的自托管支付平台。**
>
> 没有其他自托管支付网关能做到这一点。

具体含义如下：

- **一台服务器，一次安装** - 归一位超级管理员所有。
- **多个品牌** - 创建无限数量的商店（品牌）。每个品牌都是完全隔离的实体，拥有自己的自定义域名、徽标、名称、配色方案、网关、客户、账本和员工。
- **每个品牌的自定义域名** - 将 `pay.yourbrand.com` 映射到某个品牌。OwnPay 通过 DNS TXT 记录（`_ownpay-verification.{domain}`）验证所有权，并通过 A 记录检查确认路由，然后激活该域名。
- **隐形的基础设施** - 当客户进入结账页面时，他们访问的是 `pay.yourbrand.com`。他们看到的是该品牌的徽标、名称和颜色。页面上不会提及 OwnPay，没有共享域名，也没有“powered by”标识，除非品牌主动添加。
- **管理面板保持私密** - 管理仪表板只能在主安装域名上访问。自定义品牌域名对所有 `/admin/*` 路径都返回 404。
- **完全的数据隔离** - 每条客户记录、交易、账本条目、网关凭据和 Webhook 密钥都通过数据库中的 `merchant_id` 按品牌划分作用域。品牌之间零数据泄漏。
- **品牌感知的 URL** - 所有结账 URL、网关回调 URL 和 Webhook 端点都会通过 `DomainUrlService` 自动使用品牌的自定义域名构建。安装域名永远不会泄露到面向客户的流程中。

**最终效果：** 一台服务器，多个品牌。每个品牌都是一个完整、独立、完全自定义品牌的支付网关——彼此不可见，也看不到 OwnPay 的存在。

## 2. 自定义域名与白标管道 {#2-custom-domain-&-white-label-pipeline}

| 功能 | 描述 |
|:---|:---|
| 自定义域名映射 | 在 `op_domains` 中为品牌注册任意域名 |
| DNS TXT 验证 | `_ownpay-verification.{domain}` TXT 记录证明域名所有权 |
| A 记录检查 | 在激活前确认域名路由到 OwnPay 服务器 |
| 自动 DNS 复查 | `DnsVerificationJob` cron 按计划复查待处理/异常的域名 |
| 域名中间件 | 每个请求都会将 `HTTP_HOST` 与已激活域名进行匹配，并注入品牌上下文 |
| 管理路径拦截 | 在所有自定义品牌域名上，`/admin/*` 路径均返回 404 |
| 品牌 URL 构建器 | `DomainUrlService` 使用品牌域名构建所有结账、回调和重定向 URL |
| 域名缓存 | 内存缓存避免在单个请求周期内重复查询数据库 |

| CSV 导出 | 导出筛选后的交易集用于会计核算 |
| 费用跟踪 | 每笔交易分别存储 `amount`、`fee` 和 `net_amount` |

## 20. 插件系统 {#20-plugin-system}

| 功能 | 描述 |
|:---|:---|
| 插件类型 | 网关、主题、附加组件 |
| 基于清单的发现 | 每个插件在 `manifest.json` 中声明元数据、功能和钩子 |

| 手动安装 | 管理员上传 ZIP；系统解压、验证并安装 |
| 品牌级激活 | 全局启用插件或仅为特定品牌启用 |
| 插件迁移 | 插件可以包含在安装时运行的数据库迁移 |
| 设置界面 | 每个插件在 `/admin/plugins/{slug}/settings` 下注册自己的设置页面 |
| 钩子集成 | 插件通过清单注册 `doAction` / `applyFilter` 回调 |
| 卸载并清理 | 卸载时删除插件文件、数据和迁移 |

## 22. 计划任务（Cron） {#22-scheduled-jobs-cron}

| 任务 | 用途 |
|:---|:---|
| `WebhookRetryJob` | 以指数退避方式重试失败的出站 Webhook 投递 |
| `QueueWorkerJob` | 处理后台任务队列（电子邮件、导出、批量操作） |
| `BalanceVerificationJob` | 交叉核对账本余额与网关报告的余额 |
| `CurrencyUpdateJob` | 获取并更新实时汇率 |
| `SmsVerificationJob` | 处理手动网关的待处理短信验证 |
| `RefundReconciliationJob` | 从网关 API 同步退款状态 |
| `DnsVerificationJob` | 复查待处理自定义域名的 DNS 记录 |
| `UpdateCheckJob` | 轮询 OwnPay 新版本 |
| `SystemUpdateJob` | 如已配置则自动应用更新 |

由 `GET /cron/{secret}` 触发。也可以在管理设置面板中手动运行单个任务。

## 25. 安全 {#25-security}

| 功能 | 描述 |
|:---|:---|
| AES-256-GCM 加密 | 客户个人身份信息和网关凭据静态加密 |
| Argon2id 密码 | 员工和管理员密码使用 Argon2id 哈希 |
| bcrypt 回退 | 为升级兼容性保留对旧版 bcrypt 的支持 |
| CSRF 防护 | 每个会话的 CSRF 令牌；所有 POST/PUT/DELETE 请求都需要有效令牌 |
| 内容安全策略 | 每个请求的 nonce；严格的策略阻止未经授权的内联脚本 |
| HSTS | 强制启用 HTTP 严格传输安全标头 |
| X-Frame-Options | `DENY` - 防止点击劫持 |
| X-Content-Type-Options | `nosniff` - 防止 MIME 嗅探 |
| Referrer-Policy | 限制 referrer 信息泄露 |
| SSRF 防护 | `UrlValidator` 解析 Webhook URL 并将其固定到经过验证的公共 IP；禁止跟随重定向 |
| 速率限制 | 按路由、按 IP 的滑动窗口；返回带 `Retry-After` 标头的 429 |
| 登录限流 | 针对登录、密码重置和 OTP 端点的严格限流桶 |
| 基于哈希的个人身份信息搜索 | 电子邮件/电话以哈希形式存储；查找无需解密 |
| 日志清理 | `LogSanitizer` 从所有日志输出中去除密码、令牌和卡数据 |
| SQL 注入防护 | 全面使用带参数绑定的预处理语句 |
| XSS 防护 | Twig 自动转义始终开启；`|raw` 仅用于可信内容 |

## 30. REST API 接口 {#30-rest-api-surface}

三个独立的 API 层，各自采用不同的身份验证方式：

| 层 | 前缀 | 身份验证 |
|:---|:---|:---|
| 商户 API | `/api/v1/*` | Bearer API 密钥（read / write 作用域） |
| 移动配套应用 API | `/api/mobile/v1/*` | JWT（设备配对后） |
| 管理 API | `/api/admin/v1/*` | Bearer API 密钥（admin 作用域） |

完整的 API 结构及请求/响应示例：**[docs.ownpay.org](https://docs.ownpay.org)**
