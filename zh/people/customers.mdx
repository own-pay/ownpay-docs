客户是通过 OwnPay 向您付款的人。您很少需要手动创建客户档案，系统会根据已完成的付款、发票和付款链接结账自动创建。

## 客户档案的创建方式 {#how-customer-profiles-are-created}

当客户首次完成付款时，OwnPay 会将其电子邮件地址（以及电话号码，如有提供）注册为收款品牌下的客户档案。同一电子邮件地址在不同品牌中使用时，会在每个品牌下分别创建独立的客户记录。

## 客户字段 {#customer-fields}

| 字段 | 来源 | 加密 | 描述 |
| --- | --- | --- | --- |
| **Name** | 结账输入或 API 负载 | 否 | 客户全名 |
| **Email** | 结账输入或 API 负载 | 是 | 账单和收据邮箱 |
| **Phone** | 结账输入或 API 负载 | 是 | 手机或座机联系号码 |
| **IP address** | 交易元数据 | 否 | 结账时使用的 IP |
| **Total spent** | 根据交易计算 | 否 | 以品牌基础货币计的累计消费 |
| **Transaction count** | 根据交易计算 | 否 | 已完成付款的数量 |
| **Created at** | 系统时间戳 | 否 | 档案首次注册的时间 |

## PII 加密 {#pii-encryption}

OwnPay 使用 **AES-256-GCM** 对静态存储的客户电子邮件地址和电话号码进行加密。这意味着：

- 原始值绝不会以明文形式存储在数据库中。
- 只有应用程序能够使用服务器端加密密钥对其解密。
- 数据库转储或备份中这些字段仅包含密文。

拥有 **View Customers** 权限的员工可以在管理界面中看到解密后的值，但数据在存储中始终保持加密。

## GDPR 注意事项 {#gdpr-considerations}

- **访问权** - 您可以从管理界面导出客户的档案和交易历史。
- **删除权** - 对客户档案使用 **Delete** 操作。这会删除客户记录，但出于财务合规要求会保留交易记录。
- **数据最小化** - 只收集您需要的字段。除非某种付款方式需要，否则避免索要电话号码。

## 查看和搜索客户 {#view-and-search-customers}

1. 前往 **People** → **Customers**。
2. 使用**搜索栏**按姓名、电子邮件或电话号码查找客户。
3. 点击客户行打开其**详情视图**，其中显示：
   - 联系信息。
   - 包含金额、状态和日期的交易历史。
   - 累计消费汇总。

## API 中的客户数据 {#customer-data-in-the-api}

您还可以通过商户 API 以编程方式管理客户。客户记录支持创建、读取和列表操作。端点详情请参阅[商户 API 参考](/zh/api/overview)。

<Warning>
  请勿删除仍有有效发票或待处理交易的客户档案。即使您删除了档案，系统仍会出于财务合规要求保留交易记录。
</Warning>
