借助 OwnPay API，你可以创建支付、管理交易、处理退款并接收实时 webhook。本页是关于 API 工作方式的唯一权威参考——其他所有 API 页面都会链接回这里。

## 基础 URL {#base-url}

所有 API 请求都发送到 OwnPay 实例上的同一个基础路径：

```text
https://your-domain.com/api/v1
```

<Note>
  请将 `your-domain.com` 替换为你实际的 OwnPay 域名。所有端点都要求使用 HTTPS。
</Note>

## 身份验证 {#authentication}

每个请求都必须在 `Authorization` 请求头中包含 Bearer 令牌。关于如何生成、设置作用域和轮换 API 密钥，请参阅完整的 [身份验证](/zh/api/authentication) 指南。

```http
Authorization: Bearer op_live_abc123.def456
```

## 三个 API 层 {#three-api-layers}

OwnPay 提供三个不同的 API 层，每一层面向不同的使用者，并各自拥有独立的 OpenAPI 规范。

<Columns>
  <Column>
### Merchant API {#merchant-api}

    面向你的应用程序的业务操作：创建支付、列出交易、管理支付链接以及处理退款。这是你最常使用的 API。

    [查看 Merchant API 规范](/api/merchant_api.yaml)
  </Column>
  <Column>
### Mobile API {#mobile-api}

    仅供 OwnPay Android 配套应用使用。负责处理短信验证、设备配对以及基于推送的交易审批。

    [查看 Mobile API 规范](/api/mobile_api.yaml)
  </Column>
  <Column>
### Admin API {#admin-api}

    平台管理操作：管理品牌、配置网关、控制用户以及管理系统。需要更高的权限。

    [查看 Admin API 规范](/api/admin_api.yaml)
  </Column>
</Columns>

## 请求与响应格式 {#request-and-response-format}

所有请求和响应均使用 **UTF-8** 编码的 **JSON**。

### 约定 {#conventions}

| 约定 | 详情 |
| --- | --- |
| 内容类型 | `application/json` |
| 字符编码 | UTF-8 |
| 日期格式 | ISO 8601（`2024-06-15T10:30:00Z`） |
| 金额 | 通过 bcmath 处理的字符串（例如 `"5000"`、`"99.99"`） |
| 标识符 | 带前缀的字符串（`pay_...`、`txn_...`） |

<Tip>
  所有金额都以**字符串**形式返回，因为 OwnPay 使用 PHP 的 bcmath 扩展来保证精度。切勿将金额解析为浮点数——请使用你所用语言中的任意精度算术。
</Tip>

## 错误处理 {#error-handling}

每个错误响应都遵循统一的 JSON 结构。所有状态码、错误码及故障排查步骤，请参阅完整的 [错误码](/zh/api/errors) 参考。

## 幂等性 {#idempotency}

对于写入类端点（`POST`、`PATCH`、`DELETE`），你可以添加 `Idempotency-Key` 请求头以防止重复处理：

```http
Idempotency-Key: ord_1042_20240615
```

OwnPay 会存储首次请求的结果，并在 24 小时内对使用相同密钥的后续请求返回相同的响应。

## 速率限制 {#rate-limiting}

所有 API 端点都实施速率限制。OwnPay 会在每个响应中返回标准的速率限制请求头：

```http
X-RateLimit-Limit: 60
X-RateLimit-Remaining: 59
X-RateLimit-Reset: 1718000060
```

关于各级别详情和最佳实践，请参阅 [速率限制](/zh/resources/rate-limiting)。
