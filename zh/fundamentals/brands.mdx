**品牌**是 OwnPay 的多租户隔离单元。创建品牌后，您将获得一个完全独立的商户实体——拥有自己的支付网关、结账域名、视觉品牌形象、员工团队、API 密钥、客户数据库和复式记账账本——并与同一 OwnPay 实例上的其他所有品牌完全隔离。

每一条数据库查询都限定在当前品牌的 `merchant_id` 范围内。品牌 A 的员工无法看到品牌 B 的交易、客户或设置。不可能发生跨品牌的数据泄露。

## 品牌与平台 {#brand-vs-platform}

<Columns>
  <Column>
    **平台（OwnPay 实例）**

    - 主管理员账户
    - 系统级设置和插件
    - DNS 和 SSL 管理
    - 数据库服务器和 Redis
    - 运行一切的单一代码库
  </Column>
  <Column>
    **品牌（商户租户）**

    - 隔离的客户和交易
    - 独立的网关凭据
    - 独立的 API 密钥和 Webhook
    - 自定义域名和品牌形象
    - 自己的账本和余额报表
  </Column>
</Columns>

平台是基础设施，品牌则是运行在该基础设施上的商户。

## 按品牌配置 {#per-brand-configuration}

每个品牌可独立控制：

| 设置 | 说明 |
| :-- | :-- |
| **网关** | 启用哪些支付提供商及其凭据 |
| **域名** | 自定义结账域名（例如 `pay.acme.com`） |
| **品牌形象** | Logo、网站图标、配色方案、结账模板 |
| **货币和时区** | 报表使用的默认货币和时区 |
| **员工** | 拥有基于角色的权限、限定于该品牌的团队成员 |
| **API 密钥** | 独立的 Merchant 和 Mobile API 密钥对 |
| **Webhook** | 独立的 Webhook URL 和事件订阅 |
| **邮件** | SMTP 设置、发件人名称和邮件模板 |

<Info>
  账本账户同样严格限定于某个品牌。品牌 A 现金账户中的余额永远不会出现在品牌 B 的报表中。
</Info>

## 常见用例 {#common-use-cases}

| 场景 | 品牌如何运作 |
| :-- | :-- |
| **SaaS 平台运营商** | 每个客户公司都是一个品牌，拥有自己的结账体验和账本。 |
| **支付代理机构** | 每个客户都获得一个品牌，配有白标域名和隔离的财务数据。 |
| **多实体企业** | 不同部门或子公司作为独立品牌运营，使账务更清晰。 |
