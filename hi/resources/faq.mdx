## सामान्य {#general}

<AccordionGroup>
  <Accordion title="OwnPay क्या है?">
    OwnPay एक सेल्फ़-होस्टेड, ओपन-सोर्स पेमेंट ऑर्केस्ट्रेटर है। यह एक ही प्लेटफ़ॉर्म मालिक को एक इंस्टॉलेशन से कई व्हाइट-लेबल भुगतान ब्रांड (स्टोर) चलाने देता है, जिसमें 123\+ भुगतान गेटवे, डबल-एंट्री लेजर और ब्रांडों के बीच पूरा डेटा अलगाव शामिल है।
  </Accordion>

  <Accordion title="क्या OwnPay सच में मुफ़्त है?">
    हाँ। OwnPay AGPL-3.0 लाइसेंस के तहत जारी किया गया है। आप बिना किसी लाइसेंस शुल्क के इसे डाउनलोड, इंस्टॉल और उपयोग कर सकते हैं। आप केवल अपने चुने हुए भुगतान गेटवे (Stripe, bKash आदि) द्वारा लिया जाने वाला ट्रांज़ैक्शन शुल्क देते हैं, OwnPay को नहीं।
  </Accordion>

  <Accordion title="OwnPay कौन सा लाइसेंस उपयोग करता है?">
    AGPL-3.0 (GNU Affero General Public License)। इसका मतलब है कि आप OwnPay का स्वतंत्र रूप से उपयोग, संशोधन और वितरण कर सकते हैं, लेकिन नेटवर्क पर दिए जाने वाले आपके किसी भी संशोधन को भी उसी लाइसेंस के तहत उपलब्ध कराना होगा। योगदानों के लाइसेंस के विवरण के लिए [योगदान गाइड](/hi/resources/contributing) देखें।
  </Accordion>

  <Accordion title="OwnPay कितने गेटवे का समर्थन करता है?">
    OwnPay 123 बिल्ट-इन गेटवे एडॉप्टर के साथ आता है, जिनमें ग्लोबल कार्ड प्रोसेसर (Stripe, Adyen, Square), डिजिटल वॉलेट (PayPal, Apple Pay, Google Pay), मोबाइल फ़ाइनेंशियल सर्विस (bKash, Nagad, M-Pesa, GCash), buy-now-pay-later (Klarna), क्रिप्टो (Coinbase Commerce) और क्षेत्रीय प्लेटफ़ॉर्म (Razorpay, Flutterwave, Paystack, Xendit और कई अन्य) शामिल हैं।
  </Accordion>

  <Accordion title="क्या OwnPay एक SaaS प्लेटफ़ॉर्म है?">
    नहीं। OwnPay एक इंफ्रास्ट्रक्चर है जिसे आप अपने सर्वर पर डिप्लॉय करते हैं और जिसके आप मालिक हैं। किसी भी थर्ड पार्टी की आपके ट्रांज़ैक्शन, ग्राहक डेटा या कॉन्फ़िगरेशन तक पहुँच नहीं है।
  </Accordion>
</AccordionGroup>

## तकनीकी {#technical}

<AccordionGroup>
  <Accordion title="मुझे कौन सा PHP वर्ज़न चाहिए?">
    PHP 8.3 या उससे ऊपर। OwnPay हर जगह `declare(strict_types=1)` का उपयोग करता है और readonly properties तथा typed class constants जैसे PHP 8.3 फ़ीचर पर निर्भर है।
  </Accordion>

  <Accordion title="OwnPay कौन सा डेटाबेस उपयोग करता है?">
    MySQL 8.0 या MariaDB 10.4\+। OwnPay सभी तालिकाओं के लिए InnoDB का उपयोग करता है और JSON फ़ील्ड इंडेक्सिंग के लिए Stored Generated Columns पर निर्भर है।
  </Accordion>

  <Accordion title="क्या Redis आवश्यक है?">
    नहीं, लेकिन इसकी पुरज़ोर सिफ़ारिश की जाती है। OwnPay डिफ़ॉल्ट रूप से फ़ाइल-आधारित कैश और सेशन के साथ काम करता है, लेकिन Redis रेट लिमिटिंग, सेशन और जॉब क्यू के लिए काफ़ी बेहतर प्रदर्शन देता है। जब आप प्रतिदिन 1,000 से अधिक भुगतानों की उम्मीद करें, तो Redis पर स्विच करें।
  </Accordion>

  <Accordion title="क्या मैं OwnPay को Docker के साथ चला सकता हूँ?">
    हाँ। हालाँकि अभी कोई आधिकारिक Docker इमेज नहीं है, समुदाय Docker Compose कॉन्फ़िगरेशन मेंटेन करता है। OwnPay का सिंगल-एंट्री-पॉइंट आर्किटेक्चर (`public/index.php`) इसे किसी भी PHP 8.3 बेस इमेज के साथ कंटेनराइज़ करना आसान बनाता है।
  </Accordion>

  <Accordion title="क्या OwnPay शेयर्ड होस्टिंग पर काम करता है?">
    हाँ। OwnPay में एक वेब-आधारित इंस्टॉलर शामिल है जिसके लिए CLI एक्सेस की ज़रूरत नहीं है। `vendor/` डायरेक्टरी रिलीज़ आर्काइव में शामिल है, इसलिए आपको सर्वर पर Composer की ज़रूरत नहीं है। आपको PHP 8.3 समर्थन और एक MySQL डेटाबेस चाहिए।
  </Accordion>
</AccordionGroup>

## सुरक्षा {#security}

<AccordionGroup>
  <Accordion title="क्या OwnPay PCI DSS अनुपालक है?">
    OwnPay गेटवे डेलिगेशन मॉडल का उपयोग करता है - क्रेडिट कार्ड डेटा सीधे अपस्ट्रीम गेटवे (Stripe, Adyen आदि) द्वारा एकत्र और प्रोसेस किया जाता है और कभी आपके सर्वर तक नहीं पहुँचता। यह आमतौर पर OwnPay को SAQ-A के अंतर्गत रखता है, जो सबसे सरल PCI स्व-मूल्यांकन स्तर है। अपने विशिष्ट डिप्लॉयमेंट के लिए किसी QSA से परामर्श करें।
  </Accordion>

  <Accordion title="मेरा डेटा कैसे एन्क्रिप्ट किया जाता है?">
    ग्राहक PII (नाम, ईमेल, फ़ोन नंबर) और गेटवे API क्रेडेंशियल प्रति-इंस्टॉलेशन कुंजी के साथ AES-256-GCM का उपयोग करके रेस्ट पर एन्क्रिप्ट किए जाते हैं। वेबहुक पेलोड HMAC-SHA256 से साइन किए जाते हैं। सारा ट्रैफ़िक HSTS लागू करके HTTPS का उपयोग करता है।
  </Accordion>

  <Accordion title="क्या OwnPay GDPR अनुपालक है?">
    OwnPay GDPR अनुपालन के लिए तकनीकी टूल प्रदान करता है: डेटा न्यूनीकरण, एन्क्रिप्टेड स्टोरेज, हैश-आधारित लुकअप, डेटा एक्सपोर्ट (CSV), और लेजर एनोनिमाइज़ेशन के साथ डेटा हटाना। एक सेल्फ़-होस्टेड प्लेटफ़ॉर्म के रूप में, आप डेटा कंट्रोलर हैं और अपनी GDPR प्रक्रियाओं और नीतियों के लिए स्वयं ज़िम्मेदार हैं।
  </Accordion>
</AccordionGroup>

## भुगतान {#payments}

<AccordionGroup>
  <Accordion title="कौन से भुगतान गेटवे समर्थित हैं?">
    पूरी सूची [फ़ीचर](/hi/resources/features) पेज पर "Payment Gateway System" के तहत देखें। सूची में कार्ड, वॉलेट, MFS, क्रिप्टो और क्षेत्रीय प्लेटफ़ॉर्म में 123 एडॉप्टर शामिल हैं।
  </Accordion>

  <Accordion title="क्या मैं मैनुअल भुगतान (बैंक ट्रांसफ़र, नकद) स्वीकार कर सकता हूँ?">
    हाँ। OwnPay मैनुअल गेटवे का समर्थन करता है, जिनमें आप कस्टम फ़ील्ड (बैंक खाता नंबर, रेफ़रेंस नंबर) कॉन्फ़िगर करते हैं और भुगतानों को मैन्युअल रूप से या कंपैनियन ऐप के साथ SMS ऑटो-वेरिफ़िकेशन सिस्टम के ज़रिए सत्यापित करते हैं।
  </Accordion>

  <Accordion title="SMS सत्यापन कैसे काम करता है?">
    OwnPay Android कंपैनियन ऐप भुगतान प्रदाताओं से आने वाले SMS को आपके सर्वर पर फ़ॉरवर्ड करता है। सर्वर regex और ह्यूरिस्टिक पैटर्न का उपयोग करके SMS पार्स करता है, ट्रांज़ैक्शन राशि और ID निकालता है, और उसे अपने-आप किसी लंबित पेमेंट इंटेंट से मैच करता है। विवरण के लिए [फ़ीचर](/hi/resources/features) पेज देखें।
  </Accordion>
</AccordionGroup>

## डेवलपमेंट {#development}

<AccordionGroup>
  <Accordion title="प्लगइन सिस्टम कैसे काम करता है?">
    प्लगइन `modules/` के तहत स्व-निहित पैकेज होते हैं जिनमें एक `manifest.json` होता है जो मेटाडेटा, क्षमताएँ और हुक रजिस्ट्रेशन घोषित करता है। तीन प्रकार हैं: Gateway, Theme और Addon। सभी प्लगइन लोड होने से पहले एक स्टैटिक कोड सैंडबॉक्स द्वारा स्कैन किए जाते हैं। [प्लगइन डेवलपमेंट अवलोकन](/hi/developer/plugins/overview) देखें।
  </Accordion>

  <Accordion title="API रेट लिमिट क्या हैं?">
    Merchant API: प्रति API कुंजी 60 अनुरोध/मिनट। लॉगिन प्रयास: प्रति IP हर 5 मिनट में 10। ग्लोबल: प्रति IP 120 अनुरोध/मिनट। पूरे संदर्भ के लिए [रेट लिमिटिंग](/hi/resources/rate-limiting) पेज देखें।
  </Accordion>

  <Accordion title="वेबहुक कैसे काम करते हैं?">
    आप एडमिन पैनल में हर ब्रांड के लिए एक वेबहुक URL रजिस्टर करते हैं। भुगतान इवेंट होने पर OwnPay साइन किए गए HTTP POST अनुरोध (HMAC-SHA256) भेजता है। विफल डिलीवरी को एक्सपोनेंशियल बैकऑफ़ के साथ फिर से भेजा जाता है। सत्यापन कोड के लिए [कोड उदाहरण](/hi/resources/code-examples) पेज देखें।
  </Accordion>

  <Accordion title="क्या आधिकारिक SDK उपलब्ध हैं?">
    हाँ। OwnPay PHP, Laravel और Node.js के लिए आधिकारिक SDK प्रदान करता है। Python, Go और Java के लिए समुदाय द्वारा मेंटेन किए गए SDK मौजूद हैं। लिंक और इंस्टॉलेशन निर्देशों के लिए [इकोसिस्टम](/hi/resources/ecosystem) पेज देखें।
  </Accordion>
</AccordionGroup>
