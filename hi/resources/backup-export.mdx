किसी भी पेमेंट प्लेटफ़ॉर्म के लिए एक भरोसेमंद बैकअप रणनीति आवश्यक है। यह गाइड बताती है कि किसका बैकअप लें, बैकअप को कैसे स्वचालित करें, बैकअप से कैसे रीस्टोर करें, और बाहरी उपयोग के लिए डेटा कैसे एक्सपोर्ट करें।

---

## किसका बैकअप लें {#what-to-back-up}

आपको डेटा की चार श्रेणियों को सुरक्षित रखना होगा:

| श्रेणी | स्थान | सामग्री |
| :-- | :-- | :-- |
| डेटाबेस | MySQL | सभी `op_` तालिकाएँ - ट्रांज़ैक्शन, ग्राहक, लेजर, सेटिंग्स, सेशन |
| स्टोरेज फ़ाइलें | `storage/` | कैश, कंपाइल किए गए व्यू, लॉग, अपलोड की गई फ़ाइलें (लोगो, विवाद सबूत) |
| एनवायरनमेंट कॉन्फ़िग | `.env` | APP\_KEY, ENCRYPTION\_KEY, JWT\_SECRET, डेटाबेस क्रेडेंशियल्स, Redis कॉन्फ़िग |
| कस्टम कोड | `modules/`, `config/` | कस्टम प्लगइन, थीम और कॉन्फ़िग ओवरराइड |

<Warning>
  `.env` फ़ाइल में आपकी `ENCRYPTION_KEY` होती है। इसके बिना, आप डेटाबेस में संग्रहीत ग्राहक PII या गेटवे क्रेडेंशियल्स को डिक्रिप्ट नहीं कर सकते। अपने बैकअप में हमेशा `.env` शामिल करें।
</Warning>

## डेटाबेस बैकअप {#database-backup}

डंप के दौरान तालिकाओं को लॉक किए बिना एक सुसंगत स्नैपशॉट बनाने के लिए `--single-transaction` फ़्लैग के साथ `mysqldump` का उपयोग करें।

```bash
mysqldump \
  --single-transaction \
  --routines \
  --triggers \
  --set-gtid-purged=OFF \
  -u ownpay_user -p \
  ownpay_db > /backups/ownpay-db-$(date +%Y-%m-%d_%H%M%S).sql
```

<Note>
  `--single-transaction` फ़्लैग एक सुसंगत स्नैपशॉट बनाने के लिए InnoDB के MVCC का उपयोग करता है। यह प्रोडक्शन डेटाबेस के लिए सुरक्षित है क्योंकि यह reads या writes को ब्लॉक नहीं करता।
</Note>

## फ़ाइल बैकअप {#file-backup}

एप्लिकेशन फ़ाइलों को आर्काइव करें, उन dependencies को छोड़कर जिन्हें फिर से इंस्टॉल किया जा सकता है और उन अस्थायी फ़ाइलों को छोड़कर जो स्वचालित रूप से फिर से बन जाती हैं।

```bash
tar -czf /backups/ownpay-files-$(date +%Y-%m-%d_%H%M%S).tar.gz \
  --exclude='vendor' \
  --exclude='node_modules' \
  --exclude='storage/cache/*' \
  --exclude='storage/sessions/*' \
  --exclude='storage/logs/*' \
  -C /var/www ownpay/
```

फिर `.env` फ़ाइल को प्रतिबंधित अनुमतियों के साथ अलग से कॉपी करें:

```bash
cp /var/www/ownpay/.env /backups/ownpay-env-$(date +%Y-%m-%d_%H%M%S).txt
chmod 600 /backups/ownpay-env-*.txt
```

## स्वचालित बैकअप स्क्रिप्ट {#automated-backup-script}

एक shell स्क्रिप्ट बनाएँ जो टाइमस्टैम्प वाले डेटाबेस और फ़ाइल बैकअप बनाए, और डिस्क भरने से रोकने के लिए पुराने बैकअप को रोटेट करे।

```bash
#!/bin/bash
# /opt/scripts/ownpay-backup.sh

BACKUP_DIR="/backups/ownpay"
RETENTION_DAYS=30
DB_NAME="ownpay_db"
DB_USER="ownpay_user"
APP_DIR="/var/www/ownpay"

mkdir -p "$BACKUP_DIR"

# Database backup
mysqldump --single-transaction -u "$DB_USER" -p"$DB_PASS" "$DB_NAME" \
  | gzip > "$BACKUP_DIR/db-$(date +%Y-%m-%d_%H%M%S).sql.gz"

# File backup (exclude vendor, cache, sessions)
tar -czf "$BACKUP_DIR/files-$(date +%Y-%m-%d_%H%M%S).tar.gz" \
  --exclude='vendor' --exclude='node_modules' \
  --exclude='storage/cache' --exclude='storage/sessions' \
  -C /var/www ownpay/

# Rotate old backups
find "$BACKUP_DIR" -name "*.sql.gz" -mtime +$RETENTION_DAYS -delete
find "$BACKUP_DIR" -name "*.tar.gz" -mtime +$RETENTION_DAYS -delete

echo "Backup completed: $(date)"
```

इसे executable बनाएँ और cron से शेड्यूल करें:

```bash
chmod +x /opt/scripts/ownpay-backup.sh

# Run daily at 2:00 AM
crontab -e
0 2 * * * /opt/scripts/ownpay-backup.sh >> /var/log/ownpay-backup.log 2>&1
```

## अपडेट-पूर्व बैकअप {#pre-update-backups}

OwnPay की बिल्ट-इन `UpdateService` कोई भी अपडेट लागू करने से पहले स्वचालित रूप से डेटाबेस बैकअप और फ़ाइल स्नैपशॉट बनाती है। ये बैकअप `storage/backups/pre-update-{version}/` में संग्रहीत होते हैं।

<Info>
  स्वचालित अपडेट-पूर्व बैकअप एक सुरक्षा जाल हैं, आपके अपने बैकअप शेड्यूल का विकल्प नहीं। यदि अपडेट प्रक्रिया स्वयं गंभीर रूप से विफल हो जाती है (डिस्क भरी हुई, अनुमति त्रुटि), तो हो सकता है कि स्वचालित बैकअप पूरा न हुआ हो। हमेशा स्वतंत्र बैकअप बनाए रखें।
</Info>

## डेटा एक्सपोर्ट {#data-export}

अनुपालन, लेखांकन या माइग्रेशन के उद्देश्यों के लिए, आप पूर्ण डेटाबेस बैकअप के बिना डेटा एक्सपोर्ट कर सकते हैं।

- **ट्रांज़ैक्शन** - Transactions पेज पर डेट रेंज, स्थिति या गेटवे से फ़िल्टर करें, फिर **Export CSV** पर क्लिक करें। इसमें राशि, शुल्क, शुद्ध राशि, मुद्रा, स्थिति और गेटवे रेफ़रेंस शामिल होते हैं।
- **रिपोर्ट** - Reports पेज सारांश डेटा जनरेट करता है जिसे लेखांकन सॉफ़्टवेयर में इम्पोर्ट करने के लिए CSV के रूप में एक्सपोर्ट किया जा सकता है।
- **ग्राहक डेटा** - अलग-अलग ग्राहक रिकॉर्ड एक्सपोर्ट करें या किसी ब्रांड के सभी ग्राहकों को एक साथ एक्सपोर्ट करें। GDPR डेटा पोर्टेबिलिटी अनुरोधों के लिए इसमें सभी PII डिक्रिप्ट किए गए रूप में शामिल होती है।
