सबसे पहले - OwnPay में योगदान के बारे में सोचने के लिए **धन्यवाद**! 🎉 चाहे वह बग रिपोर्ट हो, नया भुगतान गेटवे हो, अनुवाद हो, डॉक्यूमेंटेशन सुधार हो या कोई फ़ीचर, हर योगदान सेल्फ़-होस्टेड, ओपन-सोर्स भुगतान इंफ्रास्ट्रक्चर को सभी के लिए बेहतर बनाने में मदद करता है।

यह गाइड बताती है कि प्रभावी ढंग से कैसे जुड़ें।

## 📜 आचार संहिता {#📜-code-of-conduct}

यह प्रोजेक्ट और इसमें भाग लेने वाला हर व्यक्ति हमारी [आचार संहिता](https://github.com/own-pay/OwnPay/blob/main/CODE_OF_CONDUCT.md) के अधीन है। भाग लेकर, आपसे इसका पालन करने की अपेक्षा की जाती है। कृपया अस्वीकार्य व्यवहार की रिपोर्ट **[ping@ownpay.org](mailto:ping@ownpay.org)** पर करें।

## 🧭 योगदान के तरीके {#🧭-ways-to-contribute}

- **🐛 बग रिपोर्ट करें** - एक स्पष्ट, दोहराने योग्य [issue](https://github.com/own-pay/OwnPay/issues) खोलें।
- **💡 फ़ीचर सुझाएँ** - एक [discussion](https://github.com/own-pay/OwnPay/discussions) या फ़ीचर अनुरोध शुरू करें।
- **🔌 गेटवे/प्लगइन बनाएँ** - कोई भुगतान गेटवे या ऐड-ऑन जोड़ें (नीचे देखें)।
- **🌍 अनुवाद करें** - कोई भाषा कैटलॉग जोड़ें या सुधारें ([TRANSLATIONS.md](/hi/developer/translations) देखें)।
- **📖 डॉक्यूमेंटेशन सुधारें** - टाइपो ठीक करें, गाइड स्पष्ट करें, उदाहरण बढ़ाएँ।
- **🧹 कोड सुधारें** - बग ठीक करें, टेस्ट जोड़ें, सावधानी से रीफ़ैक्टर करें।

> पता नहीं कहाँ से शुरू करें? **`good first issue`** या **`help wanted`** लेबल वाले इश्यू देखें।

## 🚀 सेटअप करना {#🚀-getting-set-up}

1. रिपॉज़िटरी को **फ़ोर्क** करें और अपने फ़ोर्क को क्लोन करें।
2. लोकल इंस्टेंस चलाने के लिए **[LOCAL_SETUP.md](/hi/resources/local-setup)** का पालन करें (~2 मिनट)।
3. `dev` से एक फ़ीचर ब्रांच बनाएँ (वह इंटीग्रेशन ब्रांच जिसे PR टारगेट करते हैं):

   ```bash
   git checkout dev
   git checkout -b feat/short-description
   ```

**आवश्यकताएँ:** PHP 8.3+ (`bcmath`, `json`, `mbstring`, `openssl`, `pdo_mysql`, `curl`), Composer 2, MySQL 8 / MariaDB 10.4+.

---

## 🔁 डेवलपमेंट वर्कफ़्लो {#🔁-development-workflow}

1. अपने बदलाव एक केंद्रित ब्रांच में करें (हर PR में एक तार्किक बदलाव)।
2. जिस भी व्यवहार को आप बदलें, उसके लिए टेस्ट जोड़ें या अपडेट करें।
3. पूरा लोकल चेक सूट चलाएँ (CI यही चलाता है):

   ```bash
   composer test       # PHPUnit - all tests must pass
   composer analyse    # PHPStan - must stay clean at level 9
   composer lint       # Twig + JS + CSS linting
   ```

4. स्पष्ट संदेश और **DCO sign-off** के साथ कमिट करें (नीचे देखें)।
5. अपने फ़ोर्क पर पुश करें और `dev` के विरुद्ध Pull Request खोलें।

> ✅ **समीक्षा से पहले PR को `composer test`, `composer analyse` और `composer lint` पास करने होंगे।** हरे चेक वाले PR की समीक्षा जल्दी होती है।

## 🎯 कोडिंग मानक {#🎯-coding-standards}

OwnPay गुणवत्ता का ऊँचा मानक बनाए रखता है। कृपया मौजूदा कोड और इन नियमों का पालन करें:

- **हर जगह strict types.** हर PHP फ़ाइल पहले स्टेटमेंट के रूप में `declare(strict_types=1);` से शुरू होती है (बिना BOM)।
- **PHPStan level 9 हरा रहना चाहिए।** बेसलाइन, `@phpstan-ignore` या अनावश्यक कास्ट से त्रुटियाँ न दबाएँ - मूल कारण ठीक करें।
- **पैसा हमेशा bcmath स्ट्रिंग होता है, कभी float नहीं।** वित्तीय शुद्धता पर कोई समझौता नहीं।
- **टेनेंट स्कोपिंग अनिवार्य है।** `forTenant()` / `*Scoped()` के बिना कभी भी स्कोप्ड क्वेरी न चलाएँ; `forAllTenants()` का उपयोग केवल जानबूझकर बनाए गए मालिक-स्तरीय व्यू के लिए करें।
- **URL `DomainUrlService` के ज़रिए बनाएँ** (`buildCheckoutUrl()`, `buildCallbackUrl()`) - कभी भी होस्ट हार्डकोड न करें (व्हाइट-लेबल डोमेन इसी पर निर्भर हैं)।
- **CSRF टोकन `SecurityHelpers::csrfToken()` के ज़रिए** - कभी भी `$_SESSION` को सीधे न पढ़ें।
- **केवल prepared statements।** स्ट्रिंग-इंटरपोलेटेड SQL कभी नहीं।
- **आउटपुट एस्केप करें।** Twig autoescaping चालू रहता है; अविश्वसनीय डेटा पर कभी `|raw` न लगाएँ।
- **इसे हल्का रखें।** चर्चा के बिना कोई नई भारी निर्भरता नहीं; मौजूदा फ़र्स्ट-पार्टी यूटिलिटी को प्राथमिकता दें।
- **टिप्पणियाँ *क्यों* समझाती हैं, *क्या* नहीं।** गैर-स्पष्ट निर्णयों को दर्ज करें।

पूरी फ़ीचर सूची के लिए, **[फ़ीचर संदर्भ](/hi/resources/features)** देखें। व्यापक तस्वीर के लिए, **[आर्किटेक्चर गाइड](/hi/resources/architecture)** पढ़ें।

## 🔌 भुगतान गेटवे या प्लगइन का योगदान {#🔌-contributing-a-payment-gateway-or-plugin}

गेटवे और ऐड-ऑन `modules/` के तहत प्लगइन होते हैं:

1. `manifest.json` (मेटाडेटा, क्षमताएँ, CSP origins, आइकन) के साथ `modules/gateways/<slug>/` बनाएँ।
2. `OwnPay\Gateway\GatewayAdapterInterface` को लागू करने वाली एक एडॉप्टर क्लास जोड़ें (no-op डिफ़ॉल्ट के लिए `GatewayDefaults` trait का उपयोग करें)।
3. `supportedCurrencies()` को सटीक रूप से घोषित करें ("कोई भी मुद्रा" के लिए `[]` लौटाएँ)।
4. प्लगइन को सैंडबॉक्स नियमों के भीतर रखें - कोई `exec`, `shell_exec`, `eval`, raw PDO आदि नहीं।
5. पूरे फ़्लो (initiate → callback → verify → refund) का लोकल रूप से परीक्षण करें।

पूरे कॉन्ट्रैक्ट और उदाहरणों के लिए **[गेटवे डेवलपर गाइड](https://ownpay.org/docs/developer/plugin-types/gateway-development)** देखें।

## 🌍 अनुवाद का योगदान {#🌍-contributing-translations}

OwnPay में एडमिन पैनल और ग्राहक चेकआउट दोनों के लिए पूरा i18n है। कोई भाषा जोड़ने या अपडेट करने के लिए, **[docs/TRANSLATIONS.md](/hi/developer/translations)** का पालन करें - एक dot-notation JSON कैटलॉग बनाएँ (`:placeholders` को जस का तस रखें) और मुख्य भाषाओं को `config/languages/` में रखें।

## ✍️ कमिट संदेश और DCO Sign-Off {#✍️-commit-messages-&-dco-sign-off}

हम **[Developer Certificate of Origin](https://developercertificate.org/)** (DCO) का उपयोग करते हैं। sign-off करके, आप प्रमाणित करते हैं कि आपको प्रोजेक्ट के लाइसेंस के तहत योगदान सबमिट करने का अधिकार है।

`-s` फ़्लैग का उपयोग करके हर कमिट में एक sign-off लाइन जोड़ें:

```bash
git commit -s -m "feat(gateway): add Acme Pay adapter"
```

इससे यह जुड़ जाता है:

```text
Signed-off-by: Your Name <your.email@example.com>
```

कृपया स्पष्ट संदेश लिखें। हम [Conventional Commits](https://www.conventionalcommits.org/) शैली (`feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `chore:`) को प्रोत्साहित करते हैं, हालाँकि इसे सख्ती से लागू नहीं किया जाता।

## 📥 Pull Request दिशानिर्देश {#📥-pull-request-guidelines}

- PR को केंद्रित रखें - हर एक में एक तार्किक बदलाव। बड़े काम को समीक्षा योग्य हिस्सों में बाँटें।
- PR विवरण भरें: **क्या** बदला, **क्यों**, और **कैसे परीक्षण करें**।
- संबंधित इश्यू लिंक करें (जैसे `Closes #123`)।
- कोड के साथ-साथ डॉक्यूमेंटेशन और टेस्ट अपडेट करें।
- समीक्षा फ़ीडबैक पर प्रतिक्रिया दें - हम सावधानी से समीक्षा करते हैं क्योंकि यह भुगतान सॉफ़्टवेयर है।
- सुनिश्चित करें कि सभी CI चेक हरे हैं।

## ⚖️ योगदान का लाइसेंस {#⚖️-licensing-of-contributions}

OwnPay **[GNU AGPL-3.0](https://github.com/own-pay/OwnPay/blob/main/LICENSE)** के तहत लाइसेंस प्राप्त है। योगदान सबमिट करके, आप सहमत होते हैं कि आपका काम प्रोजेक्ट के **समान AGPL-3.0** लाइसेंस के तहत लाइसेंस प्राप्त है (inbound = outbound), और आप अपने **DCO sign-off** के ज़रिए इसके मूल को प्रमाणित करते हैं। किसी अलग CLA की आवश्यकता नहीं है।
