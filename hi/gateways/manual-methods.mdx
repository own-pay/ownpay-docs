मैनुअल पेमेंट तरीके ऑफ़लाइन चैनल हैं जहाँ ग्राहक OwnPay के बाहर पेमेंट करता है - उदाहरण के लिए, आपके बैंक खाते में पैसा ट्रांसफ़र करके, मोबाइल मनी भेजकर, या कैश ऑन डिलीवरी द्वारा। आप पेमेंट निर्देश और कस्टम फ़ील्ड परिभाषित करते हैं, और फिर पेमेंट को मैन्युअल रूप से या SMS के माध्यम से स्वचालित रूप से सत्यापित करते हैं।

## मैनुअल गेटवे क्या हैं {#what-manual-gateways-are}

API गेटवे (Stripe, bKash API) के विपरीत, जो रीयल टाइम में पेमेंट प्रोसेस करते हैं, मैनुअल गेटवे इस पर निर्भर करते हैं कि ग्राहक स्वयं पेमेंट पूरा करे और फिर प्रमाण सबमिट करे। OwnPay चेकआउट इंटरफ़ेस और ट्रैकिंग प्रदान करता है, लेकिन पेमेंट वास्तव में पहुँचा या नहीं, इसकी पुष्टि आप करते हैं।

सामान्य उदाहरण:

- **बैंक ट्रांसफ़र** - ग्राहक आपके खाता नंबर पर ट्रांसफ़र करता है और एक स्क्रीनशॉट अपलोड करता है।
- **कैश ऑन डिलीवरी (COD)** - ग्राहक सामान प्राप्त होने पर पेमेंट करता है।
- **निर्देशों के साथ मोबाइल मनी** - ग्राहक आपके फ़ोन नंबर पर पैसा भेजता है और ट्रांज़ैक्शन ID दर्ज करता है।

## मैनुअल गेटवे बनाएँ {#create-a-manual-gateway}

1. **Gateways & Currencies** → **Payment Gateways** पर जाएँ।
2. **Add Manual Gateway** पर क्लिक करें।
3. बुनियादी सेटिंग्स भरें (नीचे दी गई तालिका देखें)।
4. **Create Gateway** पर क्लिक करें।

| सेटिंग | प्रकार | विवरण |
| --- | --- | --- |
| **Name** | टेक्स्ट | चेकआउट पर प्रदर्शित नाम (उदाहरण के लिए "Bank Transfer - IBBL") |
| **Slug** | टेक्स्ट | URL-सुरक्षित पहचानकर्ता (केवल लोअरकेस, हाइफ़न) |
| **Icon** | फ़ाइल अपलोड | चेकआउट पर दिखाया जाने वाला लोगो या आइकन |
| **Payment instructions** | रिच टेक्स्ट | इस तरीके को चुनने के बाद ग्राहक को दिखने वाले निर्देश |
| **Custom fields** | JSON स्कीमा | वे फ़ील्ड जो ग्राहक को भरने होंगे (उदाहरण के लिए ट्रांज़ैक्शन ID, खाता नंबर) |
| **QR code** | फ़ाइल अपलोड | वैकल्पिक QR कोड जिसे ग्राहक पेमेंट के लिए स्कैन कर सकते हैं |
| **Min / Max amount** | संख्या | इस तरीके के लिए लेनदेन सीमाएँ |

## कस्टम फ़ील्ड {#custom-fields}

उन फ़ील्ड के लिए एक JSON स्कीमा परिभाषित करें जो ग्राहकों को चेकआउट पर भरने होंगे। उदाहरण के लिए:

```json
[
  { "name": "trx_id", "label": "Transaction ID", "type": "text", "required": true },
  { "name": "sender_account", "label": "Sender Account Number", "type": "text", "required": false }
]
```

ये फ़ील्ड ग्राहक द्वारा इस मैनुअल तरीके को चुनने के बाद चेकआउट पेज पर दिखाई देते हैं।

## मैनुअल पेमेंट कैसे काम करते हैं {#how-manual-payments-work}

1. ग्राहक चेकआउट पर मैनुअल तरीका चुनता है।
2. उन्हें आपके **पेमेंट निर्देश** (बैंक खाता, फ़ोन नंबर, आदि) दिखते हैं।
3. वे स्वयं पेमेंट पूरा करते हैं।
4. वे **कस्टम फ़ील्ड** भरते हैं (उदाहरण के लिए अपनी ट्रांज़ैक्शन ID दर्ज करते हैं)।
5. लेनदेन **awaiting verification** (सत्यापन की प्रतीक्षा) स्थिति में चला जाता है।
6. आप प्रमाण की समीक्षा करते हैं और **Mark Completed** या **Mark Failed** पर क्लिक करते हैं।

SMS के माध्यम से स्वचालित सत्यापन के लिए, [SMS सत्यापन](/hi/gateways/sms-verification) देखें।

## सामान्य गलतियाँ {#common-mistakes}

| गलती | यह क्यों मायने रखती है | समाधान |
| --- | --- | --- |
| अस्पष्ट पेमेंट निर्देश | ग्राहक नहीं जानता कि पैसा कहाँ भेजना है | सटीक खाता नंबरों के साथ स्पष्ट, चरण-दर-चरण निर्देश लिखें |
| ट्रांज़ैक्शन ID के लिए कोई कस्टम फ़ील्ड नहीं | आप पहचान नहीं सकते कि कौन-सा पेमेंट किस लेनदेन का है | हमेशा कम से कम एक ट्रांज़ैक्शन ID फ़ील्ड आवश्यक करें |
| न्यूनतम राशि अधिकतम राशि से अधिक | चेकआउट सभी राशियों को अस्वीकार कर देगा | सुनिश्चित करें कि न्यूनतम राशि अधिकतम राशि से कम या उसके बराबर है |
| स्लग में स्पेस | चेकआउट URL टूट जाते हैं | केवल लोअरकेस अक्षर, संख्याएँ और हाइफ़न का उपयोग करें |

<Warning>
  मैनुअल पेमेंट तब तक "awaiting verification" में रहते हैं जब तक आप या SMS ऑटो-सत्यापन सिस्टम उन्हें प्रोसेस नहीं करते। अगर आप SMS सत्यापन का उपयोग नहीं कर रहे हैं, तो Transactions पेज नियमित रूप से जाँचें।
</Warning>
