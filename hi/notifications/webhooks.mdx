Webhooks आपके बाहरी सिस्टम को OwnPay में इवेंट होने पर रीयल-टाइम नोटिफ़िकेशन प्राप्त करने देते हैं। हर webhook पेलोड HMAC-SHA256 से साइन किया जाता है ताकि आप उसकी प्रामाणिकता सत्यापित कर सकें। Webhook प्रबंधन [Developer Hub](/hi/security/developer-hub) में होता है।

## webhook एंडपॉइंट बनाएँ {#create-a-webhook-endpoint}

<Steps>
  <Step>
    बाएँ साइडबार से **Developer Hub** खोलें, फिर **Webhooks** टैब पर क्लिक करें।
  </Step>
  <Step>
    **Add Endpoint** पर क्लिक करें। अपना HTTPS URL दर्ज करें - उदाहरण के लिए, `https://your-app.com/api/ownpay/webhook`।
  </Step>
  <Step>
    चेकबॉक्स सूची से वे इवेंट्स चुनें जिन्हें आप प्राप्त करना चाहते हैं। आप सभी इवेंट्स चुन सकते हैं या विशिष्ट इवेंट्स चुन सकते हैं।
  </Step>
  <Step>
    **Save** पर क्लिक करें। OwnPay एक अद्वितीय **signing secret** जनरेट करता है। इस सीक्रेट को तुरंत कॉपी करें - यह दोबारा नहीं दिखाया जाएगा।
  </Step>
</Steps>

<Warning>
  Webhook एंडपॉइंट URL को HTTPS का उपयोग करना होगा। OwnPay सादे HTTP पतों पर पेलोड डिलीवर करने से इनकार करता है।
</Warning>

## उपलब्ध इवेंट्स {#available-events}

| इवेंट | कब ट्रिगर होता है |
| --- | --- |
| `payment.completed` | कोई पेमेंट सफलतापूर्वक पूरा होता है |
| `payment.failed` | गेटवे पर कोई पेमेंट प्रयास विफल होता है |
| `payment.expired` | कोई पेमेंट लिंक या इनवॉइस बिना भुगतान के समाप्त हो जाता है |
| `refund.issued` | कोई रिफ़ंड बनाया और प्रोसेस किया जाता है |
| `refund.failed` | गेटवे पर कोई रिफ़ंड प्रयास विफल होता है |
| `customer.created` | एक नया ग्राहक रिकॉर्ड जोड़ा जाता है |
| `customer.updated` | किसी ग्राहक का विवरण बदला जाता है |
| `dispute.opened` | कोई chargeback या विवाद प्राप्त होता है |
| `dispute.resolved` | कोई विवाद अंतिम परिणाम तक पहुँचता है |

## सिग्नेचर सत्यापन {#signature-verification}

प्रत्येक webhook अनुरोध में एक `X-OwnPay-Signature` हेडर होता है जिसमें आपके signing secret का उपयोग करके रॉ पेलोड बॉडी का HMAC-SHA256 हैश होता है।

<Tip>
  पूर्ण सत्यापन एल्गोरिदम, कोड उदाहरण और लाइब्रेरी सुझावों के लिए [webhook API संदर्भ](/hi/api/webhooks) देखें।
</Tip>

## डिलीवरी और पुनः प्रयास {#delivery-and-retries}

OwnPay हर डिलीवरी प्रयास को ट्रैक करता है। जब कोई एंडपॉइंट non-2xx स्टेटस कोड लौटाता है या 10 सेकंड के बाद टाइम आउट हो जाता है, तो सिस्टम बढ़ते हुए शेड्यूल पर पुनः प्रयास करता है:

| प्रयास | देरी |
| --- | --- |
| पहला पुनः प्रयास | 1 मिनट |
| दूसरा पुनः प्रयास | 5 मिनट |
| तीसरा पुनः प्रयास | 30 मिनट |
| चौथा पुनः प्रयास | 2 घंटे |
| पाँचवाँ पुनः प्रयास | 6 घंटे |

यदि सभी पुनः प्रयास समाप्त हो जाते हैं, तो इवेंट **dead letter queue** में चला जाता है। आप Developer Hub से dead-letter वाले इवेंट्स का निरीक्षण कर सकते हैं और उन्हें मैन्युअल रूप से दोबारा भेज सकते हैं।

<Info>
  सफल डिलीवरी (2xx रिस्पॉन्स) ऑडिट के लिए रिस्पॉन्स स्टेटस कोड और रिस्पॉन्स बॉडी के साथ लॉग की जाती हैं।
</Info>

## webhook का परीक्षण करें {#test-a-webhook}

किसी भी एंडपॉइंट के बगल में **Test Webhook** बटन पर क्लिक करके एक नमूना `payment.completed` पेलोड भेजें। यह डेवलपमेंट के दौरान लाइव होने से पहले आपके सिग्नेचर सत्यापन लॉजिक और एंडपॉइंट रूटिंग की जाँच करने के लिए उपयोगी है।
