ग्राहक वे लोग हैं जो OwnPay के माध्यम से आपको भुगतान करते हैं। आपको शायद ही कभी ग्राहक प्रोफ़ाइल मैन्युअल रूप से बनाने की ज़रूरत पड़ती है - सिस्टम उन्हें पूरे हुए पेमेंट, इनवॉइस और पेमेंट लिंक चेकआउट से स्वचालित रूप से बनाता है।

## ग्राहक प्रोफ़ाइल कैसे बनती हैं {#how-customer-profiles-are-created}

जब कोई ग्राहक पहली बार भुगतान पूरा करता है, तो OwnPay उसके ईमेल पते (और यदि दिया गया हो तो फ़ोन नंबर) को उस ब्रांड के अंतर्गत ग्राहक प्रोफ़ाइल के रूप में दर्ज करता है जिसे भुगतान मिला। अलग-अलग ब्रांड में उपयोग किया गया एक ही ईमेल पता प्रति ब्रांड अलग-अलग ग्राहक रिकॉर्ड बनाता है।

## ग्राहक फ़ील्ड {#customer-fields}

| फ़ील्ड | स्रोत | एन्क्रिप्टेड | विवरण |
| --- | --- | --- | --- |
| **Name** | चेकआउट इनपुट या API पेलोड | नहीं | ग्राहक का पूरा नाम |
| **Email** | चेकआउट इनपुट या API पेलोड | हाँ | बिलिंग और रसीद ईमेल |
| **Phone** | चेकआउट इनपुट या API पेलोड | हाँ | मोबाइल या लैंडलाइन संपर्क नंबर |
| **IP address** | ट्रांज़ैक्शन मेटाडेटा | नहीं | चेकआउट के दौरान उपयोग किया गया IP |
| **Total spent** | ट्रांज़ैक्शन से गणना | नहीं | ब्रांड की बेस मुद्रा में कुल आजीवन खर्च |
| **Transaction count** | ट्रांज़ैक्शन से गणना | नहीं | पूरे हुए पेमेंट की संख्या |
| **Created at** | सिस्टम टाइमस्टैम्प | नहीं | प्रोफ़ाइल पहली बार कब दर्ज हुई |

## PII एन्क्रिप्शन {#pii-encryption}

OwnPay ग्राहक ईमेल पतों और फ़ोन नंबरों को **AES-256-GCM** का उपयोग करके at rest एन्क्रिप्ट करता है। इसका अर्थ है:

- मूल मान डेटाबेस में कभी भी plaintext में संग्रहीत नहीं होते।
- केवल एप्लिकेशन ही सर्वर-साइड एन्क्रिप्शन कुंजी का उपयोग करके उन्हें डिक्रिप्ट कर सकता है।
- डेटाबेस डंप या बैकअप में इन फ़ील्ड के लिए केवल ciphertext होता है।

**View Customers** अनुमति वाले स्टाफ़ सदस्य एडमिन UI में डिक्रिप्ट किए गए मान देख सकते हैं, लेकिन स्टोरेज में डेटा एन्क्रिप्टेड ही रहता है।

## GDPR संबंधी विचार {#gdpr-considerations}

- **एक्सेस का अधिकार** - आप एडमिन UI से किसी ग्राहक की प्रोफ़ाइल और ट्रांज़ैक्शन इतिहास एक्सपोर्ट कर सकते हैं।
- **मिटाने का अधिकार** - ग्राहक प्रोफ़ाइल पर **Delete** क्रिया का उपयोग करें। यह ग्राहक रिकॉर्ड हटा देता है लेकिन वित्तीय अनुपालन के लिए ट्रांज़ैक्शन रिकॉर्ड सुरक्षित रखता है।
- **डेटा न्यूनीकरण** - केवल वही फ़ील्ड एकत्र करें जिनकी आपको ज़रूरत है। जब तक किसी पेमेंट तरीके के लिए आवश्यक न हो, फ़ोन नंबर माँगने से बचें।

## ग्राहक देखें और खोजें {#view-and-search-customers}

1. **People** → **Customers** पर जाएँ।
2. नाम, ईमेल या फ़ोन नंबर से ग्राहक खोजने के लिए **search bar** का उपयोग करें।
3. ग्राहक का **विवरण दृश्य** खोलने के लिए उसकी पंक्ति पर क्लिक करें, जो दिखाता है:
   - संपर्क जानकारी।
   - राशि, स्थिति और तारीखों के साथ ट्रांज़ैक्शन इतिहास।
   - आजीवन खर्च का सारांश।

## API में ग्राहक डेटा {#customer-data-in-the-api}

आप Merchant API के माध्यम से भी ग्राहकों को प्रोग्रामैटिक रूप से प्रबंधित कर सकते हैं। ग्राहक रिकॉर्ड create, read और list संचालन सपोर्ट करते हैं। एंडपॉइंट विवरण के लिए [Merchant API संदर्भ](/hi/api/overview) देखें।

<Warning>
  जिन ग्राहक प्रोफ़ाइल के सक्रिय इनवॉइस या pending ट्रांज़ैक्शन हैं, उन्हें न हटाएँ। प्रोफ़ाइल हटाने के बाद भी सिस्टम वित्तीय अनुपालन के लिए ट्रांज़ैक्शन रिकॉर्ड सुरक्षित रखता है।
</Warning>
