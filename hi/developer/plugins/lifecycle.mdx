## चरणों का विवरण {#stage-details}

### अपलोड {#upload}

आप एडमिन पैनल में **System → Plugins → Upload** पर एक ZIP फ़ाइल अपलोड करते हैं। `PluginSandbox` आर्काइव को स्कैन करता है:

- एक मान्य `manifest.json` की जाँच करता है
- प्लगइन प्रकार और स्लग फ़ॉर्मेट को सत्यापित करता है
- ब्लॉक किए गए फ़ंक्शन (`eval`, `exec`, आदि) के लिए PHP फ़ाइलों को स्कैन करता है
- कोई भी जाँच विफल होने पर अपलोड को अस्वीकार कर देता है

### इंस्टॉल {#install}

यदि अपलोड सत्यापन में पास हो जाता है:

1. ZIP को `plugins/{slug}/` में एक्सट्रैक्ट किया जाता है
2. `manifest.json` को पार्स करके `op_plugins` डेटाबेस टेबल में संग्रहीत किया जाता है
3. `migrations/` में मौजूद डेटाबेस माइग्रेशन एक ट्रांज़ैक्शन के अंदर क्रम से चलते हैं
4. प्लगइन `installed` स्थिति में प्रवेश करता है

<Note>
  इंस्टॉल प्लेटफ़ॉर्म-स्तरीय है - यह एक बार होता है, चाहे आपके पास कितने भी ब्रांड हों।
</Note>

### सक्रिय करें {#activate}

सक्रियण **प्रति-ब्रांड** होता है। जब आप किसी ब्रांड के लिए प्लगइन सक्रिय करते हैं:

1. प्लगइन क्लास का इंस्टेंस बनाया जाता है
2. `register()` कॉल किया जाता है - हुक और फ़िल्टर रजिस्टर होते हैं
3. `boot()` कॉल किया जाता है - प्लगइन सेवाओं और कंटेनर तक पहुँच सकता है
4. `routes/api.php` और `routes/web.php` से रूट लोड किए जाते हैं
5. प्लगइन उस ब्रांड के लिए `running` स्थिति में प्रवेश करता है

```php
public function register(EventManager $events, Container $container): void
{
 // Called once per brand activation
 $events->addAction('payment.transaction.completed', $this->onPayment(...));
}

public function boot(): void
{
 // Called after register, all services are available
 $this->service = $this->container->get(MyService::class);
}
```

### निष्क्रिय करें {#deactivate}

निष्क्रिय करना भी प्रति-ब्रांड होता है:

- इस प्लगइन द्वारा ब्रांड के लिए रजिस्टर किए गए सभी हुक हटा दिए जाते हैं (`removeByOwner`)
- रूट अनलोड कर दिए जाते हैं
- **डेटा सुरक्षित रहता है** - डेटाबेस टेबल, सेटिंग्स और फ़ाइलें बनी रहती हैं

### अनइंस्टॉल {#uninstall}

अनइंस्टॉल **अपरिवर्तनीय** और प्लेटफ़ॉर्म-स्तरीय है:

1. सभी माइग्रेशन एक ट्रांज़ैक्शन के अंदर उलट दिए जाते हैं (`down()` मेथड)
2. `op_plugins` पंक्ति हटा दी जाती है
3. सभी प्लगइन फ़ाइलें डिस्क से हटा दी जाती हैं
4. डेटाबेस में संग्रहीत सेटिंग्स हटा दी जाती हैं

<Warning>
  अनइंस्टॉल स्थायी है। अनइंस्टॉल के बाद आप प्लगइन डेटा पुनर्प्राप्त नहीं कर सकते - नए सिरे से शुरू करने के लिए ZIP फिर से अपलोड करें।
</Warning>

### पुनः इंस्टॉल {#reinstall}

किसी प्लगइन को पुनः इंस्टॉल करने के लिए, ZIP फिर से अपलोड करें। यदि मैनिफ़ेस्ट संस्करण अधिक है, तो OwnPay कोई भी नए माइग्रेशन क्रमिक रूप से चलाता है (यह ट्रैक करता है कि कौन-से माइग्रेशन चल चुके हैं)।

## ब्रांड-स्तरीय बनाम प्लेटफ़ॉर्म-स्तरीय {#brand-level-vs-platform-level}

| ऑपरेशन | दायरा | उदाहरण |
| --- | --- | --- |
| अपलोड | प्लेटफ़ॉर्म | ZIP एक बार अपलोड करें |
| इंस्टॉल | प्लेटफ़ॉर्म | माइग्रेशन एक बार चलते हैं |
| सक्रिय करें | प्रति ब्रांड | Brand A के लिए Stripe सक्षम करें लेकिन Brand B के लिए नहीं |
| निष्क्रिय करें | प्रति ब्रांड | हटाए बिना अक्षम करें |
| अनइंस्टॉल | प्लेटफ़ॉर्म | सभी निशान हटाएँ |

## अपडेट फ़्लो {#update-flow}

1. `manifest.json` में उच्च `version` के साथ एक नया ZIP अपलोड करें
2. OwnPay संस्करण वृद्धि का पता लगाता है और कोई भी नए माइग्रेशन चलाता है
3. मौजूदा डेटा सुरक्षित रहता है
4. यदि प्लगइन किसी ब्रांड के लिए सक्रिय है, तो उसे स्वचालित रूप से फिर से बूट किया जाता है
