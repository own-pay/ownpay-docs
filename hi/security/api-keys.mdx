API keys आपको ब्राउज़र लॉगिन फ़्लो से गुज़रे बिना OwnPay की तीन API परतों पर प्रोग्रामेटिक अनुरोधों को ऑथेंटिकेट करने देती हैं। हर key के निर्धारित स्कोप होते हैं जो सीमित करते हैं कि वह किस तक पहुँच सकती है।

<Info>
  हस्ताक्षर निर्माण सहित पूर्ण ऑथेंटिकेशन तंत्र के लिए, [API ऑथेंटिकेशन](/hi/api/authentication) देखें।
</Info>

## API key बनाएँ {#generate-an-api-key}

<Steps>
  <Step>
    बाएँ साइडबार में **Developer Hub \> API Keys** पर जाएँ।
  </Step>
  <Step>
    **Generate New Key** पर क्लिक करें।
  </Step>
  <Step>
    वह **API परत** चुनें जिस तक यह key पहुँचेगी: Admin API, Merchant API या Mobile API।
  </Step>
  <Step>
    एक या अधिक **स्कोप** चुनें:

    | स्कोप | अनुमति |
    | --- | --- |
    | `read` | संसाधन देखें (ट्रांज़ैक्शन, ग्राहक आदि) |
    | `write` | संसाधन बनाएँ और संशोधित करें |
    | `admin` | सिस्टम कॉन्फ़िगरेशन सहित पूर्ण पहुँच |
  </Step>
  <Step>
    पहचान के लिए वैकल्पिक रूप से एक **लेबल** जोड़ें (उदाहरण के लिए, "WooCommerce Integration")।
  </Step>
  <Step>
    **Create** पर क्लिक करें। पूरी key केवल एक बार दिखाई जाती है। इसे तुरंत कॉपी करें - यह दोबारा नहीं दिखाई जाएगी।
  </Step>
</Steps>

<Warning>
  API keys को पासवर्ड की तरह मानें। उन्हें कभी भी सोर्स कोड, लॉग फ़ाइलों या सार्वजनिक रिपॉज़िटरी में commit न करें। इसके बजाय environment variables या किसी secrets manager का उपयोग करें।
</Warning>

## Key मेटाडेटा {#key-metadata}

सूची में हर API key यह दिखाती है:

| कॉलम | विवरण |
| --- | --- |
| **Label** | आपके द्वारा दिया गया पठनीय नाम |
| **API Layer** | Admin, Merchant या Mobile |
| **Scopes** | इस key को दी गई अनुमतियाँ |
| **Last Used** | सबसे हाल के API अनुरोध का टाइमस्टैम्प |
| **Last IP** | सबसे हाल के अनुरोध का IP पता |
| **Actions** | Revoke |

## Key रद्द करें {#revoke-a-key}

किसी भी key पंक्ति पर **Revoke** पर क्लिक करें। key तुरंत अमान्य हो जाती है - उस key का उपयोग करने वाला कोई भी बाद का API अनुरोध `401 Unauthorized` रिस्पॉन्स लौटाता है।

<Note>
  रद्दीकरण स्थायी है। यदि आपको पहुँच बहाल करनी है तो एक नई key बनाएँ।
</Note>

## प्रति key रेट लिमिट {#rate-limits-per-key}

हर API key रेट लिमिटिंग के अधीन है। सीमा पार करने पर `Retry-After` हेडर के साथ `429 Too Many Requests` रिस्पॉन्स लौटाया जाता है।

| API परत | सीमा |
| --- | --- |
| Admin API | 120 अनुरोध प्रति मिनट |
| Merchant API | 300 अनुरोध प्रति मिनट |
| Mobile API | 60 अनुरोध प्रति मिनट |

<Info>
  विस्तृत रेट लिमिटिंग व्यवहार और burst allowances के लिए, [रेट लिमिटिंग](/hi/resources/rate-limiting) देखें।
</Info>

## सुपर-एडमिन API key निर्माण {#super-admin-api-key-generation}

सुपर-एडमिन `admin` स्कोप के साथ keys बना सकते हैं, जो सभी सिस्टम कॉन्फ़िगरेशन, ब्रांड प्रबंधन और यूज़र प्रबंधन एंडपॉइंट तक पूर्ण पहुँच प्रदान करता है। admin-स्कोप वाली keys केवल तभी बनाएँ जब बिल्कुल आवश्यक हो - जिन इंटीग्रेशन को केवल डेटा पहुँच या ट्रांज़ैक्शन निर्माण की आवश्यकता है, उनके लिए `read` या `write` स्कोप का उपयोग करें।
