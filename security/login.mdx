The Login page is the primary security gate of the OwnPay platform. Only pre-registered staff members and the super-administrator can sign in. Brute-force protection and secure session management protect your financial data.

## Access the login page

Open your browser and navigate to your OwnPay domain followed by the login slug:

```text
https://your-domain.com/login
```

<Note>
  The default slug is `login`, but you can customize it in [branding settings](/appearance/branding) for additional security through obscurity.
</Note>

## Login process

1. Enter your registered **email address or username**
2. Enter your **password** (case-sensitive)
3. Optionally check **Remember me** to extend your session duration
4. Click **Sign In**
5. If 2FA is enabled, enter the code from your authenticator app (see [Two-Factor Authentication](/security/two-factor))

## Rate limiting

OwnPay locks an account after repeated failed sign-in attempts. It tracks failures in two ways:

- **Per email and IP address**: the account locks for that IP after **5** failed attempts.
- **Per email across all IP addresses**: the account locks everywhere after **15** failed attempts (three times the per-IP threshold).

The first lockout lasts **5 minutes**. Each further batch of failures doubles the window (5, 10, 20 minutes) up to a cap of **30 minutes**. Attempts made while the account is locked also count as failures, so continued attempts restart and extend the lockout instead of letting it expire. The error message shows the remaining wait time, for example `Try again in about 10 minute(s)`.

Every attempt, including those rejected during a lockout, appears in the **Login Security Log** under **System** in the admin sidebar. From that log, you can click **Unlock Email** or **Unlock IP** to clear the failed attempts and lift a lockout early.

### Configure the lockout thresholds

Set these environment variables in your `.env` file to change the defaults:

| Variable | Default | Description |
| --- | --- | --- |
| `MAX_LOGIN_ATTEMPTS` | `5` | Failed attempts per email and IP before lockout. The per-email threshold is three times this value |
| `LOCKOUT_DURATION` | `300` | Base lockout window in seconds. Escalated windows never exceed 30 minutes |

OwnPay reads both values through its runtime settings, so a runtime system setting with the same key overrides the `.env` value. Missing, zero, negative, or non-numeric values fall back to the defaults.

<Warning>
  Repeated lockouts from the same IP may indicate a brute-force attack. Review the Login Security Log and consider blocking the IP at your server level.
</Warning>

## Session management

| Setting | Default | Description |
| --- | --- | --- |
| **Session timeout** | 2 hours | Idle time before the session expires |
| **Remember me duration** | 30 days | Extended session when "Remember me" is checked |
| **Concurrent sessions** | Allowed | Multiple devices can be logged in simultaneously |

Sessions are stored server-side in Redis. The session cookie is `HttpOnly` and `SameSite=Strict` to prevent cross-site attacks.

## Concurrent sessions

By default, staff can be logged in from multiple browsers and devices simultaneously. You can view and terminate active sessions from [My Account](/security/my-account).

## Login troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| `Invalid credentials` | Wrong email or password | Verify your credentials. Passwords are case-sensitive |
| `Account temporarily locked` | Too many failed attempts | Stop retrying and wait for the time shown in the message, or ask an administrator to unlock your account from the Login Security Log |
| `404 Not Found` on `/login` | Custom login slug configured | Use the correct slug from your branding settings |
| Session expires immediately | Server clock mismatch | Verify your server's NTP synchronization |
