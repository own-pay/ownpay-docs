Each brand in OwnPay can have one or more custom domains. Customers are redirected to these domains during checkout, giving you a fully branded payment experience.

## Add a domain

OwnPay maps each new domain to the active brand, so switch to the brand you want before you start.

<Steps>
  <Step>
    Navigate to **System \> Domains** and click **+ Add Domain**.
  </Step>
  <Step>
    Enter the domain name (for example, `pay.yourmerchant.com`) without `https://`.
  </Step>
  <Step>
    Select the **Domain Type**: **Checkout domain** or **API domain**. Optionally, set a **Redirect URL** for visitors who open the domain directly.
  </Step>
  <Step>
    Click **Next**. OwnPay displays the DNS records you need to configure.
  </Step>
</Steps>

## Configure DNS

The add domain wizard and the domain's **DNS Setup** tab show the exact values for your installation. You need two records at your DNS provider.

### TXT record (ownership)

| Type | Name | Value |
| --- | --- | --- |
| TXT | `_ownpay-verify.pay.yourmerchant.com` | `ownpay-verify=<token>` |

Copy the token from the wizard or the **DNS Setup** tab.

### A or CNAME record (routing)

Add one of these records:

<Columns>
  <Column>
    #### CNAME method (recommended)

    | Type | Name | Value |
    | --- | --- | --- |
    | CNAME | `pay` | `your-ownpay-instance.com` |

    OwnPay shows the host of your `APP_DOMAIN` (or `APP_URL`) as the CNAME target.
  </Column>
  <Column>
    #### A record method

    | Type | Name | Value |
    | --- | --- | --- |
    | A | `pay` | `203.0.113.10` |

    Use the **A record IP** that OwnPay shows. OwnPay detects your server's public IPv4 address, or uses `APP_SERVER_IP` when you set it.
  </Column>
</Columns>

<Tip>
  The CNAME method is preferred because it automatically follows IP changes if you migrate servers.
</Tip>

### Servers behind Cloudflare or NAT

Verification compares the brand domain's A record with the server IP that OwnPay shows. That IP must be your origin server, not a proxy address.

If the shown IP is a Cloudflare edge address, the Domains page displays a warning. Verification can't pass until you fix it:

1. Set your origin server's public IPv4 address in `.env`:

   ```bash
   APP_SERVER_IP=203.0.113.10
   ```

2. Reload the Domains page and confirm the A record IP matches your origin server.
3. Point the brand domain's A record at that IP and set it to **DNS only** in Cloudflare. A proxied brand domain resolves to Cloudflare edge addresses and fails verification.

Set `APP_SERVER_IP` also when your server sits behind NAT and can't detect its own public IP.

## Verify a domain

After setting your DNS records, click **Verify DNS** in the wizard or on the domain's **DNS Setup** tab. OwnPay checks the TXT record first, then checks that the A record points to the server IP.

OwnPay also re-checks unverified domains every hour. If a domain stays unverified for 7 days, OwnPay removes it.

<Info>
  DNS propagation can take up to 48 hours, though most registrars propagate within minutes. If verification fails immediately, wait and retry.
</Info>

## SSL auto-provisioning

Once a domain is verified, OwnPay automatically requests a free SSL certificate via Let's Encrypt (or your configured ACME provider). The certificate is renewed automatically before expiry.

<Warning>
  SSL provisioning requires port **80** to be reachable from the internet for the HTTP-01 challenge. If your server is behind a firewall or reverse proxy, ensure port 80 traffic reaches OwnPay.
</Warning>

## Multiple domains per brand

You can assign multiple domains to a single brand. The first verified domain becomes the **primary domain** used in generated payment links. Additional domains serve as aliases - payments work on any verified domain.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| Verification fails | DNS not propagated | Wait and retry, or check with `dig` or `nslookup` |
| `TXT record not found` | TXT record missing or token copied incorrectly | Check the TXT name and value against the **DNS Setup** tab, then verify again |
| `A record ... does not point to ...` | A record points to a proxy edge IP, or DNS hasn't propagated | Set `APP_SERVER_IP` to your origin IP and turn off the Cloudflare proxy for the brand domain, or wait and retry |
| SSL provisioning fails | Port 80 blocked | Open port 80 or configure your reverse proxy to forward ACME challenges |
| Domain shows "mixed content" | Hard-coded HTTP links | Ensure your Application URL in Settings uses `https://` |
