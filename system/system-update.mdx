OwnPay provides a one-click update system that keeps your instance current with the latest features, security patches, and bug fixes.

## Check for updates

Navigate to **System \> System Update**. The page shows your current version and whether a newer release is available. If a newer release exists, the page displays its version number and a summary of changes.

<Info>
  You can also check the [OwnPay GitHub releases](https://github.com/own-pay/OwnPay) page for the full changelog.
</Info>

## Update process

<Steps>
  <Step>
    Click **Check for Updates** to query the update server.
  </Step>
  <Step>
    If an update is available, review the changelog and click **Update Now**.
  </Step>
  <Step>
    OwnPay automatically creates a full backup of your current installation (files and database) before applying the update.
  </Step>
  <Step>
    The update downloads and extracts the new version, runs database migrations, and clears caches.
  </Step>
  <Step>
    OwnPay redirects you to the login page once the update completes.
  </Step>
</Steps>

## Update from a ZIP package

If your server can't reach the update server, or you want to apply a specific release, you can upload an update package from your computer instead. Only superadmins see the **Manual Update via ZIP Upload** card and can use it.

The package must meet these requirements:

- It's a `.zip` file no larger than 50 MB.
- It contains a `version.json` file at the root with a `version` field.
- Every file besides `version.json` must live under one of the approved directories: `src`, `config`, `templates`, `public`, `database` and `modules`.
- It contains no symbolic links and no paths that point outside the installation.

<Steps>
  <Step>
    Navigate to **System \> System Update** and scroll to **Manual Update via ZIP Upload**.
  </Step>
  <Step>
    Select the `.zip` file and click **Validate & Preview Update**. OwnPay checks the package and rejects it with an error message if any requirement fails.
  </Step>
  <Step>
    Review the preview. It shows:
    - the target version
    - your current version
    - whether the package is an upgrade, the same version or a downgrade
    - the file name
    - the package size
    - the signature status
  </Step>
  <Step>
    Click **Apply Update Now** and confirm. Stay on the page until the update finishes. OwnPay reloads the page when the update succeeds.
  </Step>
  <Step>
    OwnPay creates a full backup, enters maintenance mode, extracts the package, runs database migrations, clears caches and runs health checks. It then exits maintenance mode.
  </Step>
</Steps>

If any step fails after the backup exists, OwnPay restores the backup automatically and exits maintenance mode. The update history records each manual update with the uploading admin and the file name.

<Warning>
  An unsigned package shows **None (unsigned upload)** as its signature status, and you can still apply it. Only upload packages you built yourself or downloaded from [OwnPay GitHub releases](https://github.com/own-pay/OwnPay/releases). If a package includes a `signature.sig` file, OwnPay applies it only when the signature verifies.
</Warning>

## Post-update steps

After every update, perform these checks:

1. **Log in** and verify the dashboard loads correctly
2. **Check the Environment Info** panel in [Settings](/system/settings) to confirm the new version
3. **Test a checkout** on at least one brand to ensure payment flows work
4. **Review plugin compatibility** - some plugins may need updates after a major OwnPay release

<Tip>
  OwnPay automatically clears the Redis cache after an update. If you see stale data, manually refresh the page.
</Tip>

## Rollback procedure

If something goes wrong after an update, you can roll back to the previous version:

<Steps>
  <Step>
    Navigate to **System \> System Update**.
  </Step>
  <Step>
    If a rollback is available, click **Rollback to v**{{version}}.
  </Step>
  <Step>
    OwnPay restores the backup created before the update.
  </Step>
  <Step>
    Verify the rollback by checking the version in Settings \> Environment Info.
  </Step>
</Steps>

<Warning>
  Rollback restores files and database to the pre-update state. Any transactions processed between the update and the rollback are preserved in the database - they are not reverted.
</Warning>

## Update via CLI

For advanced users or automated deployment pipelines, you can update OwnPay from the command line:

```bash
php /path/to/ownpay/artisan update:run
```

This command performs the same backup-and-update flow as the web UI. Use `--no-backup` to skip the automatic backup if you have your own backup strategy.

<Info>
  For migration guidance between major versions, see the [Migration Guide](/resources/migration-guide).
</Info>
