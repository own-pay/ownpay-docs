The OwnPay API lets you create payments, manage transactions, handle refunds, and receive real-time webhooks. This page is the single canonical reference for how the API works - every other API page links back here.

## Base URL

All API requests go to a single base path on your OwnPay instance:

```text
https://your-domain.com/api/v1
```

<Note>
  Replace `your-domain.com` with your actual OwnPay domain. All endpoints require HTTPS.
</Note>

## Authentication

Every request must include a Bearer token in the `Authorization` header. See the full [Authentication](/api/authentication) guide for how to generate, scope, and rotate your API keys.

```http
Authorization: Bearer op_live_abc123.def456
```

## Three API layers

OwnPay exposes three distinct API layers, each serving a different audience and backed by its own OpenAPI specification.

<Columns>
  <Column>
    ### Merchant API

    Business operations for your application: create payments, list transactions, manage payment links, and handle refunds. This is the API you will use most often.

    [View Merchant API spec](/api/merchant_api.yaml)
  </Column>
  <Column>
    ### Mobile API

    Used exclusively by the OwnPay Android companion app. Handles SMS verification, device pairing, and push-based transaction approvals.

    [View Mobile API spec](/api/mobile_api.yaml)
  </Column>
  <Column>
    ### Admin API

    Platform management operations: manage brands, configure gateways, control users, and administer the system. Requires elevated permissions.

    [View Admin API spec](/api/admin_api.yaml)
  </Column>
</Columns>

## Request and response format

All requests and responses use **JSON** with **UTF-8** encoding.

### Conventions

| Convention | Detail |
| --- | --- |
| Content type | `application/json` |
| Character encoding | UTF-8 |
| Date format | ISO 8601 (`2024-06-15T10:30:00Z`) |
| Monetary amounts | Strings via bcmath (e.g. `"5000"`, `"99.99"`) |
| Identifiers | Prefix-prefixed strings (`pay_...`, `txn_...`) |

<Tip>
  All monetary amounts are returned as **strings** because OwnPay uses PHP's bcmath extension for precision. Never parse amounts as floats - use arbitrary-precision arithmetic in your language.
</Tip>

## Error handling

Every error response follows a consistent JSON structure. See the full [Error codes](/api/errors) reference for all status codes, error codes, and troubleshooting steps.

## Idempotency

For write endpoints (`POST`, `PATCH`, `DELETE`), you can include an `Idempotency-Key` header to prevent duplicate processing:

```http
Idempotency-Key: ord_1042_20240615
```

OwnPay stores the result of the first request and returns the same response for subsequent requests with the same key within a 24-hour window.

## Rate limiting

All API endpoints enforce rate limits. OwnPay returns standard rate-limit headers on every response:

```http
X-RateLimit-Limit: 60
X-RateLimit-Remaining: 59
X-RateLimit-Reset: 1718000060
```

See [Rate limiting](/resources/rate-limiting) for tier details and best practices.
