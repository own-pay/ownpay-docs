The hook system is the primary way plugins interact with OwnPay core. It uses WordPress-style **actions** (fire-and-forget) and **filters** (data pipeline) implemented by `OwnPay\Event\EventManager`.

## API summary

### Actions

```php
// Register
$events->addAction(string $hook, callable $callback, int $priority = 10, int $acceptedArgs = 1): void;

// Fire (core only)
$events->doAction(string $hook, mixed ...$args): void;
```

### Filters

```php
// Register
$events->addFilter(string $hook, callable $callback, int $priority = 10, int $acceptedArgs = 2): void;

// Apply (core only)
$result = $events->applyFilter(string $hook, mixed $value, mixed ...$args): mixed;
```

Callbacks execute in ascending priority order (lower number = runs earlier). Default priority is 10.

## When to use actions vs filters

| Use an action when you want to... | Use a filter when you want to... |
|---|---|
| React to an event (payment completed) | Modify data before it is saved |
| Send a notification | Change a template path |
| Write to an external API | Add or remove items from a list |
| Log something | Transform a value in a pipeline |

## Hook catalog

### Payment hooks

| Hook | Type | Parameters | Description |
|---|---|---|---|
| `payment.intent.created` | Action | `array $intent` | Checkout intent generated |
| `payment.intent.expired` | Action | `array $intent` | Intent timed out without payment |
| `payment.transaction.created` | Action | `array $transaction` | Transaction entered as `pending` |
| `payment.transaction.completed` | Action | `array $transaction` | Transaction settled successfully |
| `payment.transaction.failed` | Action | `array $transaction` | Transaction declined or errored |
| `payment.transaction.cancelled` | Action | `array $transaction` | Customer cancelled |
| `payment.transaction.before_create` | Filter | `array $data`, `int $merchantId` → `array` | Modify columns before DB insert |
| `payment.amount.calculate` | Filter | `string $amount`, `array $context` → `string` | Adjust amounts (fees, surcharges) |
| `payment.fee.calculate` | Filter | `string $fee`, `array $context` → `string` | Override dynamic settlement fees |

### Gateway hooks

| Hook | Type | Parameters | Description |
|---|---|---|---|
| `gateway.capture.before` | Filter | `array $params`, `string $slug`, `int $merchantId` → `array` | Modify params sent to gateway adapter |
| `gateway.capture.after` | Action | `array $response`, `string $slug` | After gateway returns a response |
| `gateway.webhook.{slug}` | Action | `array $payload`, `string $slug` | Incoming webhook for a specific gateway slug |

<Note>
The `{slug}` in `gateway.webhook.{slug}` is replaced with the gateway plugin's slug (e.g. `gateway.webhook.gateway-stripe`).
</Note>

### Checkout hooks

| Hook | Type | Parameters | Description |
|---|---|---|---|
| `checkout.before` | Action | `array $transaction` | Before checkout layout renders |
| `checkout.render` | Filter | `array $data` → `array` | Filter Twig view context variables |
| `checkout.template` | Filter | `string $templatePath` → `string` | Override layout template path |
| `checkout.status.template` | Filter | `string $templatePath` → `string` | Override result page template |
| `checkout.head` | Action | None | Inject `<link>` and `<style>` tags |
| `checkout.footer` | Action | None | Inject `<script>` tags |
| `checkout.gateway.selected` | Action | `array $transaction`, `string $gateway` | Customer chose a gateway |
| `checkout.manual_verify.submitted` | Action | `array $transaction`, `array $proof` | Manual receipt uploaded |
| `checkout.csp.sources` | Filter | `array $sources` → `array` | Add allowed Content-Security-Policy origins |

### System hooks

| Hook | Type | Parameters | Description |
|---|---|---|---|
| `system.boot` | Action | None | Early bootstrap |
| `system.shutdown` | Action | None | Graceful shutdown |
| `system.request` | Filter | `Request $request` → `Request` | Filter inbound HTTP requests |
| `system.response` | Filter | `Response $response`, `Request $request` → `Response` | Filter final response payloads |
| `system.middleware.pipeline` | Filter | `array $middleware` → `array` | Add or remove global middleware |

### Admin hooks

| Hook | Type | Parameters | Description |
|---|---|---|---|
| `admin.middleware` | Filter | `array $middleware` → `array` | Add admin-specific middleware |
| `admin.menu` | Action | None | Add items to the admin sidebar |

### Plugin lifecycle hooks

| Hook | Type | Parameters | Description |
|---|---|---|---|
| `plugin.installed` | Action | `string $slug`, `array $manifest` | After ZIP extraction |
| `plugin.activated` | Action | `string $slug`, `int $migrationsCount`, `int $brandId` | Activation complete |
| `plugin.deactivated` | Action | `string $slug`, `int $brandId` | Plugin suspended |
| `plugin.uninstalled` | Action | `string $slug` | Files deleted |

## Hook registration pattern

Register all hooks inside your plugin's `register()` method. Hooks are automatically attributed to your plugin slug and cleaned up on deactivation:

```php
public function register(EventManager $events, Container $container): void
{
    $events->addAction('payment.transaction.completed', function (array $txn) use ($container): void {
        $service = $container->get(NotificationService::class);
        $service->notify($txn);
    }, priority: 15);

    $events->addFilter('payment.fee.calculate', function (string $fee, array $ctx): string {
        return bcadd($fee, '0.50', 2); // flat $0.50 fee add-on
    }, priority: 20);
}
```

## Architectural invariants

These constraints cannot be bypassed by any plugin:

1. **Security middleware is non-removable** — you cannot remove the authentication, CSRF, or TenantScope middleware from the pipeline
2. **TenantScope is non-bypassable** — every request is scoped to a brand; a plugin cannot access data from other brands
3. **Error isolation** — every callback runs in its own try/catch. A failing plugin never crashes the core
4. **BCMath for money** — all monetary values in hooks must use `bcadd`, `bcsub`, `bcmul`, `bcdiv`, `bccomp`
5. **No ledger writes from hooks** — plugins cannot post directly to the double-entry ledger
