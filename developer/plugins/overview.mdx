Plugins extend OwnPay without modifying core code. Write a plugin to add payment gateways, build custom features, redesign the checkout, or integrate with external platforms.

## Plugin sandbox

Every plugin runs inside a sandbox that enforces security constraints:

- No direct filesystem access outside the plugin directory
- No `eval()`, `exec()`, or `system()` calls
- Database queries through the provided query builder only
- Outbound HTTP via the plugin HTTP client with configurable allow-lists

<Info>
The sandbox is enforced at the PHP level. A plugin that attempts a restricted operation receives a `PluginSandboxException`.
</Info>

## Capabilities

Plugins declare capabilities in their `manifest.json`. Capabilities are permission gates that determine what system resources a plugin can access:

| Capability | What it enables |
---|---|
| `payment_process` | Process payments and refunds |
| `webhook_receive` | Register webhook endpoints |
| `admin_page` | Add pages to the admin panel |
| `api_routes` | Register custom API endpoints |
| `database` | Create and run migrations |
| `assets` | Serve CSS and JavaScript files |

See the full [Capabilities](/developer/plugins/capabilities) reference.

## Hook system

Plugins interact with OwnPay core through a WordPress-style action and filter hook system powered by `EventManager`:

- **Actions** - fire-and-forget callbacks (react to events)
- **Filters** - pipeline callbacks that transform data

```php
// React to a payment completion (action)
$events->addAction('payment.transaction.completed', function (array $txn): void {
    sendNotification($txn);
});

// Add a surcharge (filter)
$events->addFilter('payment.fee.calculate', function (string $fee, array $ctx): string {
    return bcadd($fee, '1.00', 2);
});
```

See the full [Hooks](/developer/plugins/hooks) catalog with 60+ hook points.
